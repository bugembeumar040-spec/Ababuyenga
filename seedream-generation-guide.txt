================================================================================
MODEL AUDIT — seedream_v4_5
================================================================================

WHAT IT TAKES
  quality          "basic" (up to 4K) or "high" (up to ~6K).  Default basic.
  aspect_ratio     1:1 · 4:3 · 16:9 · 3:2 · 21:9 · 3:4 · 9:16 · 2:3
  medias           role: image_references — accepts reference images
  prompt           positive only

WHAT IT DOES NOT TAKE
  NEGATIVE PROMPT. There is no such parameter. This is the single most
  important finding in this file.

All three packs carry a negative prompt block — "paste once, applies to all 11"
— covering faces, text, numbers, logos, extra fingers, camera shake, plastic
sheen and the rest. On Seedream 4.5 none of that is passed. Every exclusion
that matters has to be rebuilt inside the positive prompt.

Anything in those negative blocks that is merely a quality hedge (blurry, low
resolution, oversaturated, HDR glow) can be dropped without replacement —
Seedream at 4K does not need to be told not to be low-resolution. Only the
SEMANTIC exclusions need rebuilding, and there are exactly two that matter.


TWO RISKS, RANKED

RISK 1 — TEXT ON OBJECTS.  Highest risk in the project.
  Your house rule is burn-the-numbers-in-the-edit, so every prompt asks for a
  blank card, a blank statement, a blank screen, a blank price tag. Bytedance
  models render text unusually well, which means they render it unusually
  eagerly — a payment card is a strong prior for embossed digits and a
  statement page is a strong prior for printed rows. With no negative prompt to
  suppress it, this WILL come back wrong on some fraction of generations.
  Budget for rejects on every card, statement, tag and screen prompt.

RISK 2 — FACES ON CHARACTERS.  Second highest, but recoverable.
  AMIR and the shopkeeper must have completely blank heads. Models resist
  faceless humans strongly; it is close to the least likely thing in the
  training distribution. The packs already write this in caps, which helps.
  The referent technique below helps more.

Everything else — palette, lighting, materials, depth of field, the low-poly /
near-photoreal hybrid — is positive description already and transfers as-is.


MODEL CHOICE NOTE. Seedream 4.5 is a reasonable pick: 4K, strong prompt
adherence, reference-image support for character locking, and it is on the
unlim list. But note that its strengths in text rendering and precise control
cut against Risk 1. If blank-surface rejects run high in the pilot, the models
to try next are flux_2 (tagged prompt-adherence, no text-rendering emphasis)
and kling_omni_image. Do NOT switch to nano_banana_pro or gpt_image_2 — both
are explicitly tagged for text rendering and typography and will be worse on
precisely the failure mode that matters most here.


================================================================================
THE CONVERSION TECHNIQUE — replace negation with a referent
================================================================================

The instinct is to move the negative list into the positive prompt as "no text,
no numbers, no letters". That works poorly. Naming a thing raises its salience
even inside a negation, which is why negative prompts existed as a separate
channel in the first place.

What works is giving the absence a REASON. Describe an object that genuinely
has no text, or a person who genuinely has no face, and the model renders that
object rather than fighting an instruction.

FOR BLANK SURFACES — say what the object IS, not what it lacks:

  weak    "a payment card with no text, no numbers, no logos"
  strong  "a blank proof card in bare cream stock, unprinted, as it exists
           before the printing stage — a smooth uninterrupted surface"

  weak    "a statement page with no printing"
  strong  "a sheet of blank unprinted paper stock, ruled with a single empty
           rectangle, no type set on it"

  weak    "a phone with a blank screen and no text"
  strong  "a phone showing a plain uniform pale grey panel, a screen at rest
           before any interface has loaded"

FOR THE FACELESS HEADS — name a real object that has no face:

  weak    "a person with a COMPLETELY BLANK head, no eyes, no nose, no mouth"
  strong  "the head is a smooth featureless matte tan ovoid — the blank
           sculptural form of an artist's wooden mannequin or a milliner's
           head block, unpainted and unmarked, with no facial features
           modelled into it at all"

Keep the pack's original caps line as well. Belt and braces costs nothing here,
and the caps phrasing has already proven itself on the Klarna shoot.

RETAIN, verbatim, from every existing prompt: the palette hex values, the
lighting description, the material description, the lens and aperture, the
depth of field, and the framing clause. Those are the house style and they need
no conversion.

PILOT SET — 4 IMAGES, GENERATE THESE FIRST
================================================================================

Do not generate 35 images and sort them afterwards. Generate these four, run
the QA gate below, and only scale up once all four pass. Each one probes a
different failure mode, so a pass across all four means the prompt conversion
is sound for the whole library.

  P1  baseline           — object, no text risk, no face risk
  P2  text risk          — a payment card, the highest-risk surface
  P3  face risk          — the shopkeeper, and the locked character reference
  P4  16:9 conversion    — the long-form framing rule

Settings for all four: quality "basic" (4K is more than enough — "high" at ~6K
is wasted on a 1080p timeline and slower to iterate), no reference images on
P1/P2/P4, and see the note on P3.

================================================================================
QA GATE — audit every generation against this before accepting it
================================================================================

The brief was quality, not volume. Reject on any single failure; do not accept
a frame intending to fix it in post, because the house style has no compositing
stage and a flawed still gets a 14-second hold in the long-form.

HARD FAILURES — reject immediately, no discussion

  [ ] ANY text, digits, lettering, logo, watermark or signage anywhere in frame,
      including in soft-focus background. This is the number one reject.
  [ ] Any facial feature on any character — eyes, mouth, nose, brow, even faint
      or implied. A shadow that reads as an eye socket is a reject.
  [ ] Wrong hand anatomy: extra fingers, fused fingers, more than two hands.
  [ ] Palette drift: navy that is not #1E3A5F, terracotta that is not #E85F42,
      cream that has gone yellow or pink.

STYLE FAILURES — reject, they will not cut together with the rest

  [ ] Fully photoreal, with no low-poly / matte-clay quality. The house style is
      a hybrid; a straight photograph breaks the film.
  [ ] Fully stylised cartoon or 3D-render look with no material realism. The
      other half of the same failure.
  [ ] Flat or diffuse lighting. Every frame in this house style has ONE hard key
      and a real, directional, visible shadow. No shadow means reject.
  [ ] Background not falling to near-black. The deep falloff is the signature.
  [ ] Deep focus. Everything should have a shallow-focus plane.

COMPOSITION FAILURES — reject or regenerate with the framing clause emphasised

  [ ] 9:16 shots: subject not in the lower two-thirds, no clean caption headroom.
  [ ] 16:9 shots: subject centred rather than held to a third, no empty quadrant
      for number cards. This is the most likely conversion-rule failure.
  [ ] Horizon tilted, or the object not square to camera where the prompt says
      square.

CONSISTENCY CHECKS — only once you have more than one frame

  [ ] Does it cut against the locked Klarna and Deadbeat frames? Same world,
      same light, same materials?
  [ ] Character builds identical across every frame they appear in — same
      clothing, same proportions, same head form. Character drift between
      shots is what kills this format.

PASS RULE FOR THE PILOT. All four clean, on the checklist above, before
generating anything else. If P2 fails on text, fix the conversion and re-run P2
alone — do not proceed to the other 30 and inherit the same fault 30 times.

RUN ORDER, ONCE THE PILOT PASSES
================================================================================

  1. P3 approved and saved as the shopkeeper reference. Generate the AMIR
     equivalent (credit-card B05) and save that too. Lock both.
  2. All remaining CHARACTER frames, passing the two locked references through
     medias / image_references. Never generate a character frame without them.
  3. The halal-card pack, 9:16 — it is the next Short in production.
  4. The credit-card pack, 9:16 — only the frames you have not already shot.
  5. The long-form set, 16:9 — 13 new prompts plus the reuse list regenerated
     through the conversion rule. Largest batch, do it last, by which point the
     conversion is proven.

Use generate_image_batch for each group rather than one call per image, then
jobs_wait, then a single show_generation_by_ids. Keep batches to one aspect
ratio and one pack so a systematic fault is caught within a group rather than
scattered across the whole run.

CREDIT DISCIPLINE. Re-check the unlim block immediately before every batch, not
just at the start of the session — an allowance that expires mid-run silently
converts the remainder of the run into a credit spend.
